# T4 · 谈判 / 结盟 / 对赌 / 承诺设计

**用途**：把一句口头约定变成"对方无法反悔的锁"；或在别人拉你对赌时判断该不该、怎么改。
**关键前提**：原书规则里**参与者不能拒绝赌命**——所以目标不是"礼貌拒绝"，而是
"让赌局不成立 / 让对手失去赌命资格 / 抢占裁决结构"。见 `methodology/04-bets-commitment.md`。

**变量**
- `{{标的}}`：赌什么（钱/道/命/记忆/资格）
- `{{对手}}`：类型、筹码、他最在乎什么
- `{{判定函数}}`：怎么算赢（谁判定、平局怎么算、时限）
- `{{筹码}}`：我押什么、他押什么
- `{{时限}}`：什么时候必须结算

---

```text
在 {{PACK_ROOT}} 下工作。先判断这个赌局值不值得存在，再谈怎么设计。

标的：{{标的}}
对手：{{对手}}
判定函数/裁决者：{{判定函数}}
双方筹码：{{筹码}}
时限：{{时限}}

执行步骤：
1. `python3 qixia.py pattern show P4`，按"七要素"（标的/对手/判定函数/筹码/时间/制裁/裁决者）检查缺哪一项。
2. 判断合同能不能筛出类型：
   `python3 qixia.py run screening --theta-h <高类型价值> --theta-l <低类型价值> --prior <先验>`
   对照案例：`python3 qixia.py run signaling --file cases/gt/g3b_signaling_contract_fixed.json`
   （说明"押道"筛不出人、"押命"才出现分离均衡）。
3. 判断赔付结构：`python3 qixia.py run bluff --pot <池> --bet <注>`（扣掉抽水/场地费后是否仍正 EV）。
4. 判断对手的反制：`python3 qixia.py pattern counter P4`。
5. 若涉及多方同时履约/无法确认：`python3 qixia.py run common --file cases/gt/g10_common_liangjun.json`。

输出格式：
① 该不该玩：一句话 + 触发判断的关键数字（EV / 分离均衡是否存在 / 判定函数是否清晰）
② 七要素表：每项"已定义/未定义/谁解释"，未定义的给出补丁措辞（只描述功能，不写话术）
③ 不对称设计：怎么让我输得少、赢得多（期权式/条件式/平局算输/不作为算失败）
④ 不可撤回装置：让对方退不出的机制，以及它自身的失败条件
⑤ 二阶承诺：如果对手也锁死我，我的解耦方式是什么
⑥ 反制清单：对手最可能的三招 + 每招的应对
⑦ 一条红线：出现什么情形必须立刻放弃这个赌局

禁止：设计"让对方无法拒绝"的胁迫式方案；假设对手会守信；给出没有裁决者的对赌。
```

**失败信号**：七要素里"裁决者"仍为空 → 这个赌局在结构上不可执行，先别谈价码。
