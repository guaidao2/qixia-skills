# T5 · 复盘（把一局变成参数更新）

**用途**：一局结束后，把"我以为"换成"实际频率"，并更新下次的硬门禁。
**反模式**：把一次样本当成对手的稳定偏差（见 `skills/game-theory/SKILL.md` §6 反模式）。

**变量**
- `{{原计划}}`：当时打算怎么做、依据哪个模式/模型
- `{{实际过程}}`：按时间顺序，只写事实
- `{{结果}}`：赢/输/平，代价是什么

---

```text
在 {{PACK_ROOT}} 下工作。做一次结构化复盘，只输出可复用的更新项，不写感想。

原计划：{{原计划}}
实际过程（时间顺序）：
{{实际过程}}
结果与代价：{{结果}}

执行步骤：
1. 找出"计划与实际的第一个分叉点"，说明当时缺哪条信息。
2. 对涉及的模式跑 `python3 qixia.py pattern premortem <P?>`，标出事后命中的失败条件。
3. 对涉及的模型跑一次对应 solver（如需数字），核对当时的估计与事后事实的差距：
   - 贝叶斯类：当时的先验/似然 vs 事后频率
   - 沉没成本类：`python3 qixia.py run sunk --file cases/gt/g7b_sunk_opponent.json`
   - 赌注类：`python3 qixia.py run bluff --pot <实际池> --bet <实际注>`
4. 判断这次是"被剥削"还是"方差"：样本量是否足以支持结论。

输出格式：
① 分叉点：哪一步开始偏离，缺的是什么信息（信息差/规则差/承诺差）
② 失败条件命中表：哪条 fail_if 提前写过、哪条没写（没写的最重要）
③ 参数更新：具体数值的改动（先验、对手频率、成本估计），每条注明样本量
④ 下次的硬门禁：最多三条，必须可判定（能回答"是/否"）
⑤ 一句话教训：下次遇到同类局面，第一个动作是什么

禁止：用"运气不好"解释、在单次样本上宣称"读懂了他"、只写感受不写数值。
```

**失败信号**：③ 里出现"对手很激进"这类形容词 → 换成频率或金额。
