# 博弈论决策 skill（齐夏式破局 / 布局的工程化版本）

```yaml
name: game-theory-decision
version: 1.0.0
entrypoint: scripts/gt/qixia_gt.py
language: python3 (仅标准库, 无需安装依赖)
verified: 39 self-tests + 20 case reports
```

> 这份 skill 解决的是一个具体缺口：**"只有故事，没有可用工具"**。
> 它把《十日终焉》里齐夏面对的那些局，映射到 12 个标准博弈论/机制设计模型上，
> 并且**每个模型都有可执行脚本**：喂结构化参数进去，吐出结论、动作、反制、失败条件、以及"规则未定义处"清单。

```bash

```

Agent 调用约定：
- 所有子命令支持 `--json`，返回结构化结果，字段固定为
  `model / solver / title / verdict / evidence[] / numbers{} / action / counter / fail_if[] / gaps[]`
- `gaps[]` 是本 skill 的特色输出：**规则里没写清楚、因而可以被利用/被反利用的地方**（齐夏式破局的入口）。
- `--out <file>` 可直接把人类可读报告落盘。

## 2. 总决策流水线（S0 → S6，进入任何新局都按这个顺序）

| 步骤 | 做什么 | 对应脚本 | 铁律 |
|---|---|---|---|
| **S0 规则侦察** | 抄全规则原文，标"已定义/未定义/谁解释"，找判定函数、平局、时限、隐藏权限 | `mechanism`, `audit` | 没有规则全文，不要做任何承诺或下注 |
| **S1 信息盘点** | 列状态与先验 → 算后验与 EVPI → 决定值不值得花钱取证 | `bayes` | 对手主动给的信息一律降权 |
| **S2 结构识别** | 写成收益矩阵 → 判 PD/协调/胆小鬼/零和 → 找纯均衡，没有才随机化 → 算 MDF/诈唬比 | `pd`, `mixed`, `bluff` | 结构误判 = 方向性错误（最致命的错） |
| **S3 顺序与承诺** | 画博弈树 → 逆向归纳 → 剔除不可信威胁 → 算先手价值 → 设计自缚承诺；算止损线 | `backward`, `sunk` | 终局结算者可改写胜负时，树要重画 |
| **S4 机制设计** | 设计菜单让人自选（低档扭曲、高档付租）→ 校验 DSIC/IR/预算 → 补漏洞 | `screening`, `mechanism` | 给低类型留租金 = 所有人都装低类型 |
| **S5 终局审计** | 追问目标是谁定的、赢了谁结算 → 抓规则制定权/退出权/掀桌威胁 → 设第二层目标 | `meta` | 只优化别人给的目标 = 替别人打工 |
| **S6 复盘** | 记录对手实际频率 → 更新先验 → 判断可剥削还是过拟合 | 全部 | 样本不足时不要宣称"读懂了他" |

## 3. 从"故事"到"参数"的五步实例化法

模型跑不起来，99% 是参数没落地。按这五步把局面翻译成脚本能吃的 JSON：

1. **列出决策者**：谁在选？（我 / 对手 / 裁判 / 结算者）。裁判和结算者也算玩家，漏掉他们是最常见的错。
2. **列出动作与顺序**：同时动 → 收益矩阵（G1/G5）；有先后 → 博弈树（G6）；由规则分配 → 机制表（G4/G11）。
3. **列出收益的来源**：钱/道/命/记忆/队友/时间。**不能货币化的项要显式折算**（例如"被处决 = −100"），并在 case 的 `note` 里写清"这是建模假设"。
4. **填数字化参数**：概率、底池、下注额、贴现因子、类型先验。原文没给的，自己设一个并标注为假设——**结构正确比数字精确更重要**。
5. **跑三遍**：基准值、悲观值、乐观值。如果结论在三个数值下都一致，这个结论才可以用；不一致说明胜负取决于那个参数，去查那个参数。

JSON 字段速查：`skills/game-theory/SCHEMAS.md`

## 4. 判定 checklist（下注前的最后一道闸）

完整版：`skills/game-theory/checklists.md`（12 组，共 60+ 条）。最小版本只有五问：

1. **规则原文**我看全了吗？平局/时限/解释权/隐藏权限写清楚了吗？
2. **收益顺序**我确认过吗？（是 PD 还是胆小鬼？该强硬还是该合作？）
3. **对手的威胁**在最后一步对他自己有利吗？不利 = 不可信，不要让步。
4. **赔付结构**扣掉抽水/场地费之后还是正 EV 吗？
5. **赢了之后**谁结算？他能不能改判？我有退出/掀桌选项吗？

> 任何一问答不上来 → 停在 S0，别进入 S2 以后的所有步骤。

## 6. 反模式（这套工具最容易被误用的七种方式）

1. **把模型当真理**：模型只对参数负责；参数错了结论必然错，而参数来自你的侦察（S0）。
2. **跳过 S0 直接算**：收益矩阵写错一个格，后面全反。
3. **把不可信威胁当真**：过度让步比硬碰硬更常见也更致命。
4. **忽略抽水**：名义 +EV、实际 −EV 是最常见的慢性死法。
5. **在单次事件上谈频率**：一次抽样不构成对手偏差的证据（S6）。
6. **把"均衡"当"最优"**：均衡是"没人能单方面改进"，不代表你能赢；EV<0 的博弈，均衡也救不了你。
7. **忘了元层**：局内全胜、结算层归零（道的骗局）。

## 9. 已知限制（诚实声明）

- 数值参数多数是**建模假设**（原文只给规则文本，不给收益数字）；每个 case 的 `note` 字段都标注了这一点。结论的"结构"可信，"绝对数值"不可当成原文事实。
- `signaling` 只枚举纯策略 PBE（两类型×两信号×两动作）；连续类型或三动作信号需要扩展。
- `mechanism` 限于两人单物品、报告空间两值；多人/多物品需专用实现。文本层漏洞仍靠 checklist 人工判断。
- `backward` 要求完全信息、完美记忆的有限树；涉及隐藏信息时需先转成 G2/G3。
- `mixed` 的 n×m 支撑枚举上限为 4×4（精确有理数解），更大矩阵请用 `bluff`/闭式解或外部工具。
