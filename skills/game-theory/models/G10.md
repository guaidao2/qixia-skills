# G10　共同知识与协调不可能（两军问题）

**标准模型**：Common Knowledge / Coordination Impossibility (Two Generals)
**脚本入口**：`python3 scripts/gt/qixia_gt.py common --file <json>`　（`--json` 输出机器可读结果）
**原书锚点**：人蛇面试「两军问题」；第460章 未曾提及的规则；十人以上协同类游戏（不插队/送信人）
**何时用**：需要多方同时行动才能成功 / 通信不可靠或需多轮确认 / 有人可能叛变/理解偏差

## 1. 形式化定义
**两军问题**：两支军队需同时进攻，信道每条消息以概率 $p$ 送达。任何有限轮确认后，最后一条消息的送达与否
永远不是共同知识。形式化：共同知识要求 $p^k(\cdot)$ 对所有 $k$ 成立（Aumann 的共同知识公理），
有限轮只能达到 $k$ 阶知识。

**工程替代**：$n$ 轮确认后的协同成功率 $=p^n$（$p<1$ 时随 $n$ **递减**，因为每一轮都再乘一次 p）；
要达目标 $\tau$ 最多允许 $n\le\lfloor \ln\tau/\ln p\rfloor$ 轮——$p=0.9,\tau=0.99$ 时无解。

**替代方案**：① 单点决策 + 回执（把协调降维成「听令」）；② 容错行动（任一方单独行动也不致命）；
③ 多路径冗余（把有效 $p$ 提上去）；④ 可验证签名（对付奸细）。

## 3. 决策流程（照做即可）

- 1) 承认结论：在不可靠信道上，『绝对共同知识』无法通过有限轮确认达成（每一轮都留下最后一层不确定）。
- 2) 用概率工程替代完美协调：n 轮确认后协同成功率 = p^n，算出需要的轮数与冗余（多信使/多路径）。
- 3) 若 p^n 无法达标：改变机制——指定单一决策者（独裁）+ 可验证信号，或把行动设计成『任一方单独行动也不致命』。
- 4) 把『理解的共同性』也当成信道：用书面、复述确认、可执行演练来降低歧义。

## 4. 判定 checklist（任一不过 → 不要下注）

- [ ] 需要的是『同时行动』还是『先后行动』？先后可以直接消除协调问题。
- [ ] 信道可靠性 p 是多少？我是否在假设 p=1？
- [ ] 失败的代价是否对称？若只有一方承担，他会不确认就行动。
- [ ] 是否存在叛徒（奸细）？有叛徒时任何协议都可能被破坏（G1）。

## 5. 危险信号 / 反制 / 失败条件

**危险信号**：『我们都说好了』但没有可验证的确认；依赖口头转述的多层指挥链

**反制**：
- 降级为单点决策+回执
- 多路径冗余通信
- 设计容错行动（局部失败不导致全局失败）

**失败条件（踩中任意一条=这套策略会送你死）**：
- 追求绝对确认 -> 永远不动，错过窗口
- 假设一次沟通=共同知识 -> 协同失败

## 6. 建模假设（不可外推的部分）

- p=0.9 是假设值；原文没有给出消息可靠性。
- 模型只处理「成功/失败」二元信道；若信道可被篡改（奸细伪造确认），需在协议层加签名，结论更悲观。
