# G12　终局结算与元博弈（目标函数审计）

**标准模型**：Terminal Settlement / Meta-Game & Objective Audit
**脚本入口**：`python3 scripts/gt/qixia_gt.py meta --file <json>`　（`--json` 输出机器可读结果）
**原书锚点**：第337章 道的骗局；第1063章 布局开始；第1082章 最终博弈；第1347章 神之欺诈；十城收集目标与「洗牌」
**何时用**：所有局都赢了，但不确定赢了之后会发生什么 / 目标本身可能是别人设定的诱饵 / 需要判断『谁在结算这场游戏』

## 1. 形式化定义
**元博弈**：局内博弈 $G$ 的收益由「结算者」$J$ 定义，而 $J$ 有自己的目标 $v_J$。
把目标写成 $g=\phi(\text{局内结果};\theta_J)$，则
$$\text{我的真实收益}=\mathbb{1}[J \text{ 承认结果}]\cdot u_i - \text{清算风险}$$

**三个必问**：
1. 目标函数是谁写的？（若 $g$ 由对手给出，则 $g$ 可能是诱导函数）
2. 结算者能否改写结果？（$J$ 的单方面修改权 = 我的收益不是我的）
3. 我有没有「掀桌」选项？（退出/同归于尽的可信威胁 = 谈判力的来源，见 G6）

**二层目标设计**：表面目标（赢下本局）+ 真实目标（获得下一局的规则制定权 / 退出权 / 结算权）。

## 3. 决策流程（照做即可）

- 1) 问：这个目标是谁定的？他从中得到什么？（道的骗局：集齐不是出路，是洗牌触发器）
- 2) 问：结算者能否在我赢之后改写结果？（规则更改/第三方赌约/抹杀裁判）
- 3) 若结算者不可信：把胜利条件改成『结算者也必须履约』的结构（把裁判拖进赌局）。
- 4) 设计二层目标：表面目标（赢下这一局）+ 真实目标（获得下一局的规则制定权）。
- 5) 留后手：任何单局胜利都必须有『胜利后仍能自保』的备份（底牌/撤退路线/新世界）。

## 4. 判定 checklist（任一不过 → 不要下注）

- [ ] 我的目标是他给的，还是我自己定的？
- [ ] 赢了之后谁会来收账？
- [ ] 是否存在『赢了反而更危险』的结构？
- [ ] 我有没有第二目标（规则制定权/退出权）？

## 5. 危险信号 / 反制 / 失败条件

**危险信号**：目标由对手单方面宣布；奖励是『集齐X』式的进度条（可被随时改规则）

**反制**：
- 把结算权抢到自己手里
- 把胜利条件改成对手无法否认的形式
- 准备『掀桌』选项（同归于尽的可信威胁，G6）

**失败条件（踩中任意一条=这套策略会送你死）**：
- 只优化给定目标 -> 成为别人计划里的工具
- 没有掀桌选项 -> 被无限加价

## 6. 建模假设（不可外推的部分）

- 风险分（0–9）是启发式评分，不是概率；它只用来排序「先解决哪个问题」。
- 模型假设结算者有独立目标；若结算者是纯规则机器（无动机），风险分应下调。

## 7. 与其他模型的联动
G12 是总收口：G1–G11 都在「局内」，G12 决定「局本身是否是个陷阱」；它也是所有 check 的最后一道闸门。
